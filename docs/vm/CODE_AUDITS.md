## Audit Policies

- **Shared functions** (Issue #2282): Extract duplicated logic; add completeness test. Examples: `convert_value`, `extract_base_type`, the shared dispatch resolver (`inference_core/dispatch_resolver.rs`).
- **Callable values** (Issue #2312): `Function`, `Closure`, `ComposedFunction` — verify all three. See `TYPE_SYSTEM.md`.
- **Dispatch handlers** (Issue #2517, #3910): Use the shared resolver in `inference_core/dispatch_resolver.rs`; no inline scoring or `extract_base`. See `BINARY_DISPATCH.md`.
- **Rust toolchain and Clippy zero-warning policy** (Issues #2905, #3177, #3288, #5642/#5652, #11253): Rust 1.95 is the workspace MSRV and Rust 1.95.0 is the checked-in local reference toolchain. CI's explicit `stable` action is a separate moving lint-drift lane; it does not redefine either checked-in version. `scripts/run_clippy_lanes.sh` is the executable registry for the mandatory default, `repl`, `aot`, and `aot,cranelift` all-targets lanes, while `scripts/test_aot.sh` owns the generated-Rust smoke. `scripts/check_rust_toolchain_contract.sh` rejects a missing/changed toolchain pin, a workspace package that stops inheriting the MSRV, removal or weakening of a registered lane, loss of the default/AoT gate owners, or loss of current-stable CI coverage. Capture exact `rustc -Vv` and `cargo clippy -V` output when reporting toolchain-specific lint drift. Full policy and commands: `RUST_TOOLCHAIN.md`. Common patterns to avoid: `get(k).is_none()` (use `!contains_key(k)`), `map_or(true, |x| ...)` (use `is_none_or(...)`), manual `Default` for all-Option/Vec structs (use `#[derive(Default)]`), unnecessary `return` in match arms, float literals approximating math constants (see "Float test values" in `TESTING_GUIDE.md`).
- **Self-free method extraction** (Issue #2925, #3215, #3216): In `compile/` `impl CoreCompiler` blocks, methods whose body makes no `self.field` access should be standalone `pub(super) fn` functions so they can be unit-tested without constructing a full `CoreCompiler`. Common signals: name starts with `can_`, `is_`, `should_`, `static_`. When a method mixes static cases with a dynamic `self.`-dependent fallback, extract the static sub-predicate returning `Option<bool>`. Examples in `compile/stmt.rs`: `can_convert_type`, `static_iterate_strategy`.
- **Builtin ownership** (Issue #3033): Each `BuiltinId` must be in exactly ONE `builtins_*.rs` file. When adding/moving handlers, update `docs/vm/BUILTIN_OWNERSHIP.md`. Run `bash scripts/check_builtin_duplicates.sh` to verify. See `BUILTIN_OWNERSHIP.md`.
- **Wire-ID table integrity for BuiltinOp/BuiltinId/Intrinsic** (Issue #8628, parent #8611): `compile/instr_wire_ids.rs` holds the stable u32 wire IDs used to serialize these three enums into the bytecode cache (Issue #8627). Three invariants must hold: (1) every active variant in the enum has an entry in `*_to_wire_id()`; (2) no two variants share the same wire ID; (3) retired wire IDs (tombstoned with a `// Wire ID NN → RETIRED …` comment) are never reassigned to new variants. `scripts/check_instr_wire_ids.sh` enforces all three for `BuiltinOp`, `BuiltinId`, and `Intrinsic`. It must pass whenever any of these enum definitions or `instr_wire_ids.rs` is changed. Run `bash scripts/check_instr_wire_ids.sh` to verify.
- **BuiltinOp effect-classification fail-closed audit** (Issue #9323, sibling of #9270): every `BuiltinOp` that allocates a fresh mutable object (array / dict / `Ref` cell / RNG engine / `Expr` with shared `.args`) or is non-deterministic/side-effecting MUST be classified non-pure (`consistent = AlwaysFalse`) in `infer_builtin_op_effects` (`compile/effects/inference.rs`). A pure classification lets the straight-line CSE pass value-number two textually-identical calls into one aliased object — the #9270 (RNG) / #7176 (`zeros`/`ones`) / #5130 (`Ref`) miscompile class. This is enforced by a **test-based** trip-wire, not a `check_*.sh` script: the `#[test] builtin_op_effect_classification_is_audited_issue_9323` (same module) drives an **exhaustive, wildcard-free `match` in `expected_effect_class`** over all `BuiltinOp` variants, so adding a new variant makes the test build stop compiling until the author classifies it `MustNotBePure` / `PureOk`; the test then asserts `!is_pure()` / `is_pure()` accordingly against `infer_builtin_op_effects`, and cross-checks the enumerated count against `strum::VariantNames`. NEVER add a `_ =>` arm to `expected_effect_class` — that re-opens the silent-default hole. Run `cargo nextest run --release --lib -p subset_julia_vm builtin_op_effect_classification` to verify.
- **Positive boundary audit: no new domain-logic Rust builtins** (Issue #7878 / docs/COMPARISION.md P4): the other `check_*.sh` audits are *negative* (they keep retired carriers from returning). This one is the *positive* gate that stops the Layer-2 Rust builtin surface (`subset_julia_vm_bytecode/src/builtins.rs` + `subset_julia_vm_vm/src/vm/builtins_*.rs`) from silently growing with domain logic that has no performance justification. `scripts/check_no_new_domain_builtins.sh` ratchets two metrics against baselines embedded in the script: the **`BuiltinId` enum variant count** (hard ratchet) and **Layer-2 total LOC** (soft ratchet with a +300 tolerance band) — the current baseline values live in the script itself (`BASELINE_BUILTIN_COUNT` / `BASELINE_BUILTIN_LOC`), each bump recorded there with the Issue and attribution (recorded-bump procedure, Issue #9696). On a LOC-ratchet failure the audit prints a per-file LOC breakdown so the file that grew is named (and so the negative self-test has an injection-specific reason, Issue #9892). When you intentionally add a builtin, it must meet a `RUST_BOUNDARY_JUSTIFICATION.md` condition 1–4 (OS/HW, external C/Fortran lib, VM-internal metadata, or the no-JIT performance boundary); add a `// Boundary: condition N (...), Issue #NNNN` comment next to the new variant and bump the matching baseline in the same PR — otherwise implement it in Pure Julia under `subset_julia_vm/src/julia/`. When a Pure Julia migration *shrinks* the surface (e.g. #7875), lower the baselines to tighten the ratchet (non-fatal reminder). Run `bash scripts/check_no_new_domain_builtins.sh` to verify. **Local pre-PR/pre-merge registration** (Issue #9696): because Actions is disabled, this audit is also a default gate in `scripts/premerge_gate.sh`, so every guarded lead merge re-runs it and drift is caught in the PR that causes it; it remains in ci.yml's `code-audits` job and pr-fast's globbed audit batch for whenever Actions is re-enabled. Issue #10256 (after the #10247/#10241 drift pair, plus PR #10224's repeat of the same class) pairs it with `audit_base_cache_schema_fingerprint.sh` in that default gate list and adds the same-PR update checklist to `docs/vm/CHECKLISTS.md`.
- **Complex interleaved-array containment** (Issue #7876 / docs/COMPARISION.md P2): Complex arrays use an interleaved `[re0, im0, re1, im1, ...]` Rust representation with dedicated fast paths (broadcast/matmul/index/mutation/reduction). This is a deliberate no-JIT performance tradeoff (`RUST_BOUNDARY_JUSTIFICATION.md` condition 4), NOT a semantic one. `scripts/check_complex_interleaved_allowlist.sh` pins the set of files that reference the interleaved representation (marker: case-insensitive `interleav` under `subset_julia_vm_vm/src/vm`) to an explicit 18-file allowlist. A **new** file introducing interleaved-Complex code fails the audit and must (1) carry a `// Boundary: condition 4 (no-JIT perf), Issue #NNNN` comment, (2) keep a pure-Julia fallback (guarded by `tests/fixtures/complex/complex_array_fallback_parity_7876.jl`, which asserts the fast path equals the scalar Complex dispatch path), and (3) be added to the allowlist in the same PR. A stale allowlist entry is a non-fatal prune reminder. Run `bash scripts/check_complex_interleaved_allowlist.sh` to verify.
- **Rust-only semantic surface ratchet** (Issue #8673, parent #8648): complements the #7878 boundary audit from the *Pure Julia First* side. `scripts/check_rust_semantics_ratchet.sh` runs `scripts/inventory_rust_semantics.sh --summary` and ratchets two metrics against baselines embedded in the script: **`builtin_public_rust_only`** (public builtins with no Pure Julia same-name definition, baseline 95) and **`rust_semantic_surface_rust_only`** (distinct public surface functions implemented only in Rust, baseline 106) — both monotonically non-increasing. It also enforces that every inventoried `BuiltinId` / semantic `Instr` variant has a classified row (category + evidence) in `docs/vm/rust_semantics_classification.tsv` (Issue #8672 classification completeness). When a `pure-julia-migration` Issue lands, lower the baselines in the same PR (non-fatal reminder). A growth failure means: implement the public name in Pure Julia first, or justify it against `RUST_BOUNDARY_JUSTIFICATION.md` conditions 1-4, classify it in the TSV, and bump the baseline with that justification. Run `bash scripts/check_rust_semantics_ratchet.sh` to verify.
- **Thread-local registries** (Issue #3038): When adding a new thread-local registry populated during Base compilation, follow the checklist in `docs/vm/CACHE_ARCHITECTURE.md`. Key rule: `clear_cache()` must also clear the new registry, and `CachedBase` must store + replay its contents. See `CACHE_ARCHITECTURE.md`.
- **Binary error handling** (Issue #3051): `bin/` crates must not use `.expect()` for user-facing errors. Use `unwrap_or_else(|e| { eprintln!("Error: ..."); std::process::exit(1); })` instead. Run `bash scripts/check_no_expect_in_bin.sh` to verify.
- **Test assertion style** (Issue #3053, #3090, #3098): In ALL `#[cfg(test)]` blocks (both `tests.rs` files and inline modules), do not use `other => panic!()`. Use `assert!(matches!())` instead. Run `bash scripts/check_no_panic_in_tests.sh` to check the current ratchet baselines (`src/`: 81, `tests/`: 339) and reduce those baselines when refactoring existing tests. See `TESTING_GUIDE.md`.
- **VmError classification** (Issue #3078): In `vm/exec/`, every `return Err(VmError::TypeError(...))` must be annotated. Quick rule: user-triggerable → `self.raise(VmError::TypeError(...))` + `// User-visible:`; compiler-invariant → `return Err(VmError::InternalError(...))` + `// INTERNAL:`. Run `bash scripts/check_vmerror_classification.sh` to verify the current ratchet baseline (51 unannotated returns) and reduce the baseline as annotations land. See `PANIC_FREE.md`.
- **Hardcoded variable names in type inference** (Issue #3088, #3181): In `compile/expr/infer/`, do NOT add `name == "X"` checks for new struct-type constants — use the `global_types` registry instead. Primitive-type special values (`NaN`, `Inf`, `ENDIAN_BOM`, etc.) are the only legitimate exceptions. Run `bash scripts/check_no_hardcoded_var_names_in_inference.sh` to verify the current ratchet baseline (9 existing checks) and reduce it as structural fixes land.
- **Debug derives** (Issue #3096, #3108): All public types in `compile/` and `aot/` must derive `Debug` (or have a documented exception in `scripts/check_missing_debug.sh`). Workspace lint `missing_debug_implementations = "warn"` is enabled. Run `bash scripts/check_missing_debug.sh` to verify. See `TESTING_GUIDE.md`.
- **docs/vm/ reference validity** (Issue #3118): Every `FOO.md` name referenced in `CLAUDE.md` must exist as `docs/vm/FOO.md`. Run `bash scripts/check_docs_vm_refs.sh` to verify. When renaming a doc file, update `CLAUDE.md` in the same PR.
- **docs/vm markdown links and archive policy** (Issues #9008/#11263): `scripts/docs_vm_link_check.py` validates internal docs/vm markdown links and heading anchors, while requiring external URL hosts to be listed in `docs/vm/EXTERNAL_LINK_ALLOWLIST.txt`. `scripts/check_status_done_archive_budget.sh` is the read-only, fixed 3,000-line STATUS.md / DONE.md live-file budget gate from the Issue #6341 archive policy and rejects maintenance arguments; run the separate mutating `scripts/archive_status_done.sh` command to move whole dated sections verbatim into `docs/vm/archive/STATUS-<YYYY>.md` and `docs/vm/archive/DONE-<YYYY>.md`. Each archive is kept in stable newest-to-oldest order across batches; `scripts/test_archive_status_done.sh` proves multi-batch order and body preservation. Nightly `docs-maintenance` runs the equivalent `archive_status_done.sh --check` mode. Issue #11263 registers the read-only wrapper as a required default source-only guarded-premerge gate because Actions are disabled. Negative controls independently overflow STATUS and DONE, exercise the aggregate runner, and reject removal or weakening of the required registry row.
- **Fixture test name uniqueness** (Issue #3135): Fixture test `name` fields must be unique across ALL category `manifest.toml` files. The runtime uses `find()` on all merged tests — duplicates silently load the wrong file. Run `bash scripts/check_fixture_test_names.sh` to verify.
- **Fixture category canonicalization** (Issues #9671/#11053/#11065): Every directory under `subset_julia_vm/tests/fixtures/` must be listed in `docs/vm/FIXTURE_CATEGORIES.tsv`. Prevents near-synonym drift (`array`/`arrays`, `macro`/`macros`, `meta`/`metaprogramming`, …) that scatters related fixtures and breaks category-targeted nextest. Prefer consolidating a near-synonym into an existing category; #11053 moved the escaped `float64` fixture into canonical `floatfuncs`. Run `bash scripts/check_fixture_categories.sh`. It is a required `premerge_default=true` source-only registry row; negative tests exercise the checker, registry runner, and removal of the required row itself.
- **Test-binary budget** (Issue #9671): Every `subset_julia_vm/tests/*.rs` integration-test binary must be listed in `docs/vm/TEST_BINARY_ALLOWLIST.tsv`. Each binary links the full ~370k-line VM rlib, so binary count is the dominant term in full-suite build time (the only merge gate). Adding a NEW binary requires an allowlist edit that surfaces in review — prefer adding a `mod` to an existing consolidated binary (`regression_*_tests.rs`, `integration_tests.rs`). Run `bash scripts/check_test_binary_budget.sh` to verify. Negative self-test: `check_test_binary_budget.sh (unlisted test binary)` in `check_audit_negative_selftest.sh`. **Local pre-PR/pre-merge registration** (Issue #10912): this audit was CI-enforced (`ci.yml`) but missing from `scripts/premerge_gate.sh`'s default gate set — the same gate-ownership gap as #10870, which let `subset_julia_vm/tests/f64_function_block_tests.rs` (PR #10427) land unallowlisted with nothing local to catch it. It is now a `premerge_default=true` row in the canonical registry `scripts/source_only_audits.tsv`, run via `scripts/run_source_only_audits.sh` from every default `premerge_gate.sh` invocation — see the registry bullet below.
- **Dict-like builtin handlers** (Issue #3169, #3171): When adding or modifying a `BuiltinId::DictXxx` handler in `builtins_dicts.rs`, verify: (1) `try_dispatch_struct_dict` is called for Dict-named StructRefs, (2) `try_dispatch_struct_non_dict` is called before `pop_dict()`/`pop_value()` to allow custom struct dispatch, (3) a fixture test covers a non-Dict StructRef case. **DictSet arg-order**: Compilation pushes `[collection, key(args[2]), value(args[1])]`; after pop+reverse, `args.swap(1, 2)` is needed before dispatch to match `setindex!(collection, value, key)`. **LoadDict pitfall**: For Any-typed locals, use `compile_expr` instead of `LoadDict` — `LoadDict` returns empty Dict for StructRef values in `locals_any`.
- **Generated file headers** (Issue #3175): Every `.rs` file whose first line is `// @generated — do not edit manually.` must also carry a `// Re-generate with: <command>` comment and the referenced script must exist. Run `bash scripts/check_generated_files.sh` to verify.
- **Workaround Issue links** (Issue #3179): Every `// Workaround:` comment must include `(Issue #XXXX)`. If no tracking issue exists, create one with `gh issue create` first. Run `bash scripts/check_workarounds_documented.sh` to verify. See `docs/vm/WORKAROUNDS.md` for the full catalogue.
- **Workarounds–WORKAROUNDS.md sync** (Issue #3263): Every Issue number in a `// Workaround: ... (Issue #NNNN)` comment must also appear in `docs/vm/WORKAROUNDS.md`. Run `bash scripts/check_workarounds_sync.sh` to verify. When removing a workaround, move its entry to the "Resolved Workarounds" table.
- **REPLGlobals.set() Value coverage** (Issue #3267): When adding a new `Value` variant, update `repl/globals.rs` `set()` match — the `other_vars` catch-all silently accepts new variants. Add a round-trip unit test in `repl::globals::tests`. Existing completeness test: `test_all_other_vars_injectable_types_return_some()` in `repl/converters.rs`.
- **Call handler kwargs inline loops** (Issue #3324): New call handlers in `vm/exec/` must use `bind_kwargs_defaults()` or `bind_kwargs_with_map()` for kwargs binding — never inline `for kwparam in &func.kwparams` loops (they miss `is_varargs` handling). Run `bash scripts/check_call_handler_kwargs.sh` to verify (baseline: 10 known inline loops).
- **Audit script bash 3.2 compatibility** (Issue #3759, #3766, #3771, #9461): Every `scripts/check_*.sh` must run on macOS default `/bin/bash` 3.2.57 — the workflow in CLAUDE.md prescribes running these scripts locally, and CI on Linux silently masks bash-4-only constructs. `scripts/check_audit_scripts_bash3_compat.sh` forbids `mapfile`/`readarray` (replace with the portable `arr=(); while IFS= read -r line; do arr+=("$line"); done < <(producer)` pattern, guarding later splats with `"${arr[@]+"${arr[@]}"}"` so `set -u` survives empty arrays), forbids `declare`/`local`/`typeset -A` associative arrays and `declare -g` (bash-4 only; use a temp file of pairs + `sort`/`uniq -d`), and runs `bash -n` on each audit under the invoking shell so a bash-3.2 parse failure — e.g. double quotes nested inside a double-quoted `$(...)`, or a `case`/`;;` nested inside a `$(...)` — is caught locally instead of slipping to CI (Issue #9461 repaired `check_instr_wire_ids.sh`, `check_builtin_duplicates.sh`, and `check_docs_vm_refs.sh`, which broke this way while CI stayed green). Run `bash scripts/check_audit_scripts_bash3_compat.sh` to verify.
- **Bundled Base numeric width signatures** (Issues #3699 / #9381): `subset_julia_vm/src/julia/base/int.jl` must keep same-type fixed-width integer division on upstream-shaped `BitSigned` / `BitUnsigned` parametric methods instead of reintroducing explicit `function div(x::TN, y::TN)` overloads for every signed and unsigned width. More generally, new bundled Base numeric helpers should preserve upstream parametric / Union / `::Int` signatures rather than adding primitive-width method matrices. The old per-width `div` matrix prevented the generic `div(x, y) = floor(x / y)` Float64-widening bug behind Issues #3694 / #3696 / #3701, but Issue #9381 replaces that duplication with structural union dispatch. Run `bash scripts/check_div_specializations.sh` to verify the enforced `div` slice. Companion fixture matrix: `subset_julia_vm/tests/fixtures/type_preservation/*_arith_matrix.jl` plus `numeric/bitinteger_parametric_widths_9381.jl`. See `docs/vm/TYPE_PRESERVATION.md` Part 3.
- **Public Base fallback routing registry** (Issues #3893/#3911/#4276): Public Base names that retain a Rust builtin fallback must be classified in `BASE_FUNCTION_ROUTES` with a route kind and upstream Julia source reference, and mirrored in `docs/vm/PUBLIC_FALLBACKS.md`. Do not add direct string arms back to `base_function_to_builtin_op()` or hard-coded dispatch-first name lists. Direct `compile_builtin_string` fallbacks must either be route-classified or listed as an explicitly documented string fallback exemption; exemptions must be documented in `docs/vm/BUILTIN_REMOVAL.md`, `docs/vm/BUILTIN_OWNERSHIP.md`, or `docs/vm/UNIMPLEMENTED.md`. Run `bash scripts/check_base_routing_registry.sh` to verify.
- **No public `Base.<stdlib>` escape hatches** (Issue #8278): Stdlib root modules such as `LinearAlgebra`, `Random`, `Statistics`, `Dates`, `Printf`, `Test`, `InteractiveUtils`, and `Base64` are loaded as root modules (`using LinearAlgebra`), not as public `Base.<stdlib>` submodules. Compiler/module-call special cases must either target a real Base submodule (`Base.Iterators`, `Base.Broadcast`, `Base.MathConstants`, etc.) or a private bridge inside the stdlib wrapper; they must not expose `Base.<stdlib>` property access, `using Base.<stdlib>`, or `Base.<stdlib>.<fn>` routes. Run `bash scripts/check_no_public_base_stdlib_routes.sh` to verify.
- **Structural debt inventory ratchet** (Issues #8327/#8329/#8332/#8333/#8334/#8335/#8336/#8337/#8460): `scripts/check_structural_debt_inventory.sh` pins the milestone-56 design-debt inventory so broad legacy categories cannot grow while the larger refactors proceed: Rust branches on Julia package/non-primitive type names, scattered env var / target triple / artifact literals, `.unwrap()` / `.expect()` sites, cross-crate `#[path]` boundary bypasses, safe FFI exports that accept raw pointers, large Rust files/functions, inline tests under `src/`, source-side `#[cfg(test)]` blocks over 200 lines, Julia `# Workaround:` comments without issue links, stale TODO references to closed #1447/#3510, and active-source `Issue #XXXX` placeholders. This is a ratchet, not a license to add debt up to the baseline: any intentional new instance needs its own Issue and a same-PR reduction elsewhere or a justified baseline update. Public/API-level Rust tests belong in `subset_julia_vm/tests/`; keep source-side test modules only for private white-box coverage. Run `bash scripts/check_structural_debt_inventory.sh` to verify; `bash scripts/check_structural_debt_inventory.sh --update` rewrites every `BASELINES` entry in the script to the current count (bumping AND tightening) in one mechanical pass — review the diff (numeric literals only), then re-run without `--update` to confirm green; for a daily human-readable summary across this and the other ratchet audits, run `bash scripts/audit_health_report.sh --fast`. **Local pre-PR/pre-merge registration** (Issue #10870): this audit was CI-enforced (`ci.yml`) but missing from `scripts/premerge_gate.sh`'s default gate set — exactly the gap that let it drift red on `main` twice (#8740, then again #9920-#9925) with no guarded merge ever catching it. It is now a `premerge_default=true` row in the canonical registry `scripts/source_only_audits.tsv`, run via `scripts/run_source_only_audits.sh` from every default `premerge_gate.sh` invocation — see the registry bullet below.
- **Definition-order fragment merge and runtime-publication inventory** (Issues #11036/#11128/#11134/#11740): `scripts/check_definition_order_merges.sh` discovers every production `DefinitionOrderCursor::{append_fragment,insert_fragment_after}` call plus direct assignments and mutations of definition-bearing fields, including simple `&mut program.modules` aliases, then compares exact `(file, function, count)` tuples with `docs/vm/DEFINITION_ORDER_MERGE_INVENTORY.tsv`. Independent prelude/Base/REPL/package fragments must use the cursor; raw transfer is allowed only for an inventoried shared-lowering-context, already-rebased replay, post-chronology partition, or explicitly classified non-Core-IR container. The same inventory requires methods, runtime nominals, imports, and recovered module shells to declare explicit success, error-recovery, and full-rebuild replay policies; every `*_activations: Vec<...>` carrier in the REPL/session boundary must have a state row. The audit also rejects direct offset helpers outside the Core-IR owner module. Negative mutations inject a raw push, an aliased-vector push, a renamed cursor site, removal of the runtime-nominal state row, and removal of the required source-only registry row. Run `bash scripts/check_definition_order_merges.sh` after adding any Program/Module append, replay, cache restore, preload, AoT-facing path, or persistent REPL activation field.
- **Callable singleton identity authority** (Issue #11703; prevention for #11685/#9784): `CallableSingletonIdentity` is the only semantic identity for `FunctionValue` and `ClosureValue`; candidate indices are relocatable execution references and display names may collide between source callables and lowering helpers. `scripts/check_callable_singleton_identity.sh` discovers every `GeneratorCallable::*FunctionIndex` carrier, pins its persisted-rebuild fallback to identity-preserving runtime values, inventories every production VM identity-construction site, and requires comparison, deep copy, reflection, and runtime type keys to consume the stable authority. The consolidated carrier matrix covers `FunctionValue`, `ClosureValue`, plain/tuple-splat/filtered generators, helper/source spelling collisions, owner-qualified relocation, and deep copy. Adding a callable carrier or identity consumer requires extending both the matrix and audit. Its negative self-test removes the `FunctionValue::singleton_identity` accessor and proves the audit fails.
- **Base cache schema fingerprint snapshot** (Issue #8444/#9623/#10051): `subset_julia_vm_compile/src/compile/base_cache_schema_files.txt` lists the Rust sources whose serialized shapes affect persistent/embedded Base cache compatibility (`Instr`, VM compiled-program metadata, method-table wire structs, inference cache keys, and Core/Value type schemas). `scripts/audit_base_cache_schema_fingerprint.sh` hashes those files, in `LC_ALL=C`-sorted path order, and compares the result plus `CACHE_VERSION` against `subset_julia_vm_compile/src/compile/base_cache_schema_fingerprint.txt`. Sorting (Issue #10051 slice A) makes the audited hash independent of the manifest's line order — reordering manifest entries with no content change can no longer silently change the "current" fingerprint. For the manifest as of #10051 slice A, `LC_ALL=C sort` was verified (via a `cargo:warning` probe of the real build) to also match `subset_julia_vm/build.rs::base_cache_schema_fingerprint()`'s `Vec<PathBuf>::sort()` order, but the two orderings are **not proven equal in general** — Rust's path-component `Ord` and plain byte order diverge for paths that collide at a `.`-vs-`/` component boundary (e.g. a hypothetical `value.rs` sibling of a `value/` directory) — so this audit checks the snapshot for **internal** consistency (bash-computed "current" vs the committed "snapshot", same algorithm both times), not literal equality with the runtime-embedded `SJULIA_BASE_CACHE_SCHEMA_HASH`. This audit is a CI/review-hygiene gate, not the runtime corruption guard: `deserialize_base_cache` independently recomputes `schema_fingerprint`/`enum_variant_fingerprint`/`compiler_build_fingerprint` from the current source tree at load time and rejects a mismatching cache regardless of whether this snapshot was refreshed (`docs/vm/CACHE_ARCHITECTURE.md`); this script exists so the drift is visible in PR review instead of only surfacing as a cold-start cache miss. If a schema input changes, bump `CACHE_VERSION`, then run `bash scripts/audit_base_cache_schema_fingerprint.sh --update` to rewrite the exact two-line snapshot (`CACHE_VERSION=<n>`, `SCHEMA_FINGERPRINT=<sha256>`) and `bash scripts/audit_base_cache_schema_fingerprint.sh` to verify default read-only mode is green; both failure branches (stale `CACHE_VERSION`, changed fingerprint) print this exact `--update` command. The #9623 checklist is: default mode fails on a stale/corrupt copied snapshot, `--update` repairs it, `git diff -- subset_julia_vm_compile/src/compile/base_cache_schema_fingerprint.txt` shows only the snapshot rewrite, and default mode passes afterward. ### When automation cannot update ci.yml (Issue #4714)

GitHub **OAuth** automation tokens without the `workflow` scope cannot
push changes to `.github/workflows/*.yml`. Pushes that touch those
files are rejected at the remote with:

```
remote: refusing to allow an OAuth App to create or update workflow
`.github/workflows/ci.yml` without `workflow` scope
```

**SSH key pushes are not OAuth-scoped and do work** — if the repo is
configured with an SSH remote (`git@github.com:…`), workflow file commits
pushed over SSH succeed. Confirmed during Issue #8632 PR implementation.

When the SSH remote is unavailable, pick one of these fallbacks:

1. **Push via SSH.** `git push git@github.com:AtelierArith/ailujsoi.git <branch>`
2. **Split the PR.** Land the script and the `CODE_AUDITS.md` bullet
   in this PR, and open a *separate* follow-up issue that quotes
   verbatim the diff that needs to land in `ci.yml` (shellcheck line
   plus the run step). A maintainer with `workflow` scope can apply
   the stanza in a one-line follow-up PR. See Issue #4705 for the
   reference shape (the issue body embeds the full script + ci.yml
   stanzas inline).
3. **Rename out of the audit perimeter.** If the script is
   *developer-only* and does not need CI enforcement, name it without
   the `check_*.sh` prefix so the `Verify all check_*.sh scripts are
   referenced…` audit (above) does not apply. See
   `scripts/fixture_julia_parity.sh` (PR #4713, Issue #4712) for an
   example of this pattern.

The long-term fix is to grant the automation token the `workflow`
scope so that the script + ci.yml stanza can ship in a single PR.
Issue #4714 tracks that operational change.
