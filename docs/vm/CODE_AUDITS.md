# Code Audits

Detailed code audit policies for SubsetJuliaVM. Referenced from `CLAUDE.md`.

## Audit Policies

- **Shared functions** (Issue #2282): Extract duplicated logic; add completeness test. Examples: `convert_value`, `extract_base_type`, the shared dispatch resolver (`inference_core/dispatch_resolver.rs`).
- **Callable values** (Issue #2312): `Function`, `Closure`, `ComposedFunction` — verify all three. See `TYPE_SYSTEM.md`.
- **Dispatch handlers** (Issue #2517, #3910): Use the shared resolver in `inference_core/dispatch_resolver.rs`; no inline scoring or `extract_base`. See `BINARY_DISPATCH.md`.
- **Clippy zero-warning policy** (Issue #2905, #3177, #3288, #5642/#5652): `cargo clippy --all-targets -- -D warnings` must pass with zero warnings. **Run it under each buildable feature set**, because feature-gated code (e.g. the `repl`-only `src/bin/sjulia.rs` and repl tests) is invisible to the default invocation — that is how the #5642 lints accumulated unnoticed:
  - `cargo clippy --all-targets -- -D warnings` (default)
  - `cargo clippy --all-targets --features aot -- -D warnings`
  - `cargo clippy --all-targets --features repl -- -D warnings`

  CI currently runs only the first two (`.github/workflows/ci.yml`); adding the `repl` step is blocked on the `workflow` OAuth scope (Issue #4714, tracked by #5652 — see "When automation cannot update ci.yml" below). Common patterns to avoid: `get(k).is_none()` (use `!contains_key(k)`), `map_or(true, |x| ...)` (use `is_none_or(...)`), manual `Default` for all-Option/Vec structs (use `#[derive(Default)]`), unnecessary `return` in match arms, float literals approximating math constants (see "Float test values" in `TESTING_GUIDE.md`). Run locally before opening a PR.
- **Self-free method extraction** (Issue #2925, #3215, #3216): In `compile/` `impl CoreCompiler` blocks, methods whose body makes no `self.field` access should be standalone `pub(super) fn` functions so they can be unit-tested without constructing a full `CoreCompiler`. Common signals: name starts with `can_`, `is_`, `should_`, `static_`. When a method mixes static cases with a dynamic `self.`-dependent fallback, extract the static sub-predicate returning `Option<bool>`. Examples in `compile/stmt.rs`: `can_convert_type`, `static_iterate_strategy`.
- **Builtin ownership** (Issue #3033): Each `BuiltinId` must be in exactly ONE `builtins_*.rs` file. When adding/moving handlers, update `docs/vm/BUILTIN_OWNERSHIP.md`. Run `bash scripts/check_builtin_duplicates.sh` to verify. See `BUILTIN_OWNERSHIP.md`.
- **Positive boundary audit: no new domain-logic Rust builtins** (Issue #7878 / docs/COMPARISION.md P4): the other `check_*.sh` audits are *negative* (they keep retired carriers from returning). This one is the *positive* gate that stops the Layer-2 Rust builtin surface (`builtins.rs` + `vm/builtins_*.rs`) from silently growing with domain logic that has no performance justification. `scripts/check_no_new_domain_builtins.sh` ratchets two metrics against baselines embedded in the script: the **`BuiltinId` enum variant count** (hard ratchet, baseline 246) and **Layer-2 total LOC** (soft ratchet with a +300 tolerance band, baseline 11,011). When you intentionally add a builtin, it must meet a `RUST_BOUNDARY_JUSTIFICATION.md` condition 1–4 (OS/HW, external C/Fortran lib, VM-internal metadata, or the no-JIT performance boundary); add a `// Boundary: condition N (...), Issue #NNNN` comment next to the new variant and bump the matching baseline in the same PR — otherwise implement it in Pure Julia under `subset_julia_vm/src/julia/`. When a Pure Julia migration *shrinks* the surface (e.g. #7875), lower the baselines to tighten the ratchet (non-fatal reminder). Run `bash scripts/check_no_new_domain_builtins.sh` to verify.
- **Complex interleaved-array containment** (Issue #7876 / docs/COMPARISION.md P2): Complex arrays use an interleaved `[re0, im0, re1, im1, ...]` Rust representation with dedicated fast paths (broadcast/matmul/index/mutation/reduction). This is a deliberate no-JIT performance tradeoff (`RUST_BOUNDARY_JUSTIFICATION.md` condition 4), NOT a semantic one. `scripts/check_complex_interleaved_allowlist.sh` pins the set of files that reference the interleaved representation (marker: case-insensitive `interleav` under `subset_julia_vm/src/vm`) to an explicit 18-file allowlist. A **new** file introducing interleaved-Complex code fails the audit and must (1) carry a `// Boundary: condition 4 (no-JIT perf), Issue #NNNN` comment, (2) keep a pure-Julia fallback (guarded by `tests/fixtures/complex/complex_array_fallback_parity_7876.jl`, which asserts the fast path equals the scalar Complex dispatch path), and (3) be added to the allowlist in the same PR. A stale allowlist entry is a non-fatal prune reminder. Run `bash scripts/check_complex_interleaved_allowlist.sh` to verify.
- **Thread-local registries** (Issue #3038): When adding a new thread-local registry populated during Base compilation, follow the checklist in `docs/vm/CACHE_ARCHITECTURE.md`. Key rule: `clear_cache()` must also clear the new registry, and `CachedBase` must store + replay its contents. See `CACHE_ARCHITECTURE.md`.
- **Binary error handling** (Issue #3051): `bin/` crates must not use `.expect()` for user-facing errors. Use `unwrap_or_else(|e| { eprintln!("Error: ..."); std::process::exit(1); })` instead. Run `bash scripts/check_no_expect_in_bin.sh` to verify.
- **Test assertion style** (Issue #3053, #3090, #3098): In ALL `#[cfg(test)]` blocks (both `tests.rs` files and inline modules), do not use `other => panic!()`. Use `assert!(matches!())` instead. Run `bash scripts/check_no_panic_in_tests.sh` to check the current ratchet baselines (`src/`: 81, `tests/`: 339) and reduce those baselines when refactoring existing tests. See `TESTING_GUIDE.md`.
- **VmError classification** (Issue #3078): In `vm/exec/`, every `return Err(VmError::TypeError(...))` must be annotated. Quick rule: user-triggerable → `self.raise(VmError::TypeError(...))` + `// User-visible:`; compiler-invariant → `return Err(VmError::InternalError(...))` + `// INTERNAL:`. Run `bash scripts/check_vmerror_classification.sh` to verify the current ratchet baseline (51 unannotated returns) and reduce the baseline as annotations land. See `PANIC_FREE.md`.
- **Hardcoded variable names in type inference** (Issue #3088, #3181): In `compile/expr/infer/`, do NOT add `name == "X"` checks for new struct-type constants — use the `global_types` registry instead. Primitive-type special values (`NaN`, `Inf`, `ENDIAN_BOM`, etc.) are the only legitimate exceptions. Run `bash scripts/check_no_hardcoded_var_names_in_inference.sh` to verify the current ratchet baseline (9 existing checks) and reduce it as structural fixes land.
- **Debug derives** (Issue #3096, #3108): All public types in `compile/` and `aot/` must derive `Debug` (or have a documented exception in `scripts/check_missing_debug.sh`). Workspace lint `missing_debug_implementations = "warn"` is enabled. Run `bash scripts/check_missing_debug.sh` to verify. See `TESTING_GUIDE.md`.
- **docs/vm/ reference validity** (Issue #3118): Every `FOO.md` name referenced in `CLAUDE.md` must exist as `docs/vm/FOO.md`. Run `bash scripts/check_docs_vm_refs.sh` to verify. When renaming a doc file, update `CLAUDE.md` in the same PR.
- **Fixture test name uniqueness** (Issue #3135): Fixture test `name` fields must be unique across ALL category `manifest.toml` files. The runtime uses `find()` on all merged tests — duplicates silently load the wrong file. Run `bash scripts/check_fixture_test_names.sh` to verify.
- **Dict-like builtin handlers** (Issue #3169, #3171): When adding or modifying a `BuiltinId::DictXxx` handler in `builtins_dicts.rs`, verify: (1) `try_dispatch_struct_dict` is called for Dict-named StructRefs, (2) `try_dispatch_struct_non_dict` is called before `pop_dict()`/`pop_value()` to allow custom struct dispatch, (3) a fixture test covers a non-Dict StructRef case. **DictSet arg-order**: Compilation pushes `[collection, key(args[2]), value(args[1])]`; after pop+reverse, `args.swap(1, 2)` is needed before dispatch to match `setindex!(collection, value, key)`. **LoadDict pitfall**: For Any-typed locals, use `compile_expr` instead of `LoadDict` — `LoadDict` returns empty Dict for StructRef values in `locals_any`.
- **Generated file headers** (Issue #3175): Every `.rs` file whose first line is `// @generated — do not edit manually.` must also carry a `// Re-generate with: <command>` comment and the referenced script must exist. Run `bash scripts/check_generated_files.sh` to verify.
- **Workaround Issue links** (Issue #3179): Every `// Workaround:` comment must include `(Issue #XXXX)`. If no tracking issue exists, create one with `gh issue create` first. Run `bash scripts/check_workarounds_documented.sh` to verify. See `docs/vm/WORKAROUNDS.md` for the full catalogue.
- **Workarounds–WORKAROUNDS.md sync** (Issue #3263): Every Issue number in a `// Workaround: ... (Issue #NNNN)` comment must also appear in `docs/vm/WORKAROUNDS.md`. Run `bash scripts/check_workarounds_sync.sh` to verify. When removing a workaround, move its entry to the "Resolved Workarounds" table.
- **REPLGlobals.set() Value coverage** (Issue #3267): When adding a new `Value` variant, update `repl/globals.rs` `set()` match — the `other_vars` catch-all silently accepts new variants. Add a round-trip unit test in `repl::globals::tests`. Existing completeness test: `test_all_other_vars_injectable_types_return_some()` in `repl/converters.rs`.
- **Call handler kwargs inline loops** (Issue #3324): New call handlers in `vm/exec/` must use `bind_kwargs_defaults()` or `bind_kwargs_with_map()` for kwargs binding — never inline `for kwparam in &func.kwparams` loops (they miss `is_varargs` handling). Run `bash scripts/check_call_handler_kwargs.sh` to verify (baseline: 10 known inline loops).
- **Audit script bash 3.2 compatibility** (Issue #3759, #3766, #3771): Every `scripts/check_*.sh` must run on macOS default `/bin/bash` 3.2.57 — the workflow in CLAUDE.md prescribes running these scripts locally, and CI on Linux silently masks bash-4-only constructs like `mapfile`/`readarray`. Replace with the portable `arr=(); while IFS= read -r line; do arr+=("$line"); done < <(producer)` pattern, and guard later splats with `"${arr[@]+"${arr[@]}"}"` so `set -u` survives empty arrays on bash 3.2. Run `bash scripts/check_audit_scripts_bash3_compat.sh` to verify.
- **`div` specializations per integer width** (Issue #3699): `subset_julia_vm/src/julia/base/int.jl` must carry an explicit `function div(x::TN, y::TN)` for every signed and unsigned bit width (Int8/16/32/64/128, UInt8/16/32/64/128). Without per-width specializations the generic fallback `div(x, y) = floor(x / y)` widens through Float64 because `/` on integers always returns Float64 — the recurring shape behind Issues #3694 / #3696 / #3701. Run `bash scripts/check_div_specializations.sh` to verify. Companion fixture matrix: `subset_julia_vm/tests/fixtures/type_preservation/*_arith_matrix.jl`. See `docs/vm/TYPE_PRESERVATION.md` Part 3.
- **Public Base fallback routing registry** (Issues #3893/#3911/#4276): Public Base names that retain a Rust builtin fallback must be classified in `BASE_FUNCTION_ROUTES` with a route kind and upstream Julia source reference, and mirrored in `docs/vm/PUBLIC_FALLBACKS.md`. Do not add direct string arms back to `base_function_to_builtin_op()` or hard-coded dispatch-first name lists. Direct `compile_builtin_string` fallbacks must either be route-classified or listed as an explicitly documented string fallback exemption; exemptions must be documented in `docs/vm/BUILTIN_REMOVAL.md`, `docs/vm/BUILTIN_OWNERSHIP.md`, or `docs/vm/UNIMPLEMENTED.md`. Run `bash scripts/check_base_routing_registry.sh` to verify.
- **No public `Base.<stdlib>` escape hatches** (Issue #8278): Stdlib root modules such as `LinearAlgebra`, `Random`, `Statistics`, `Dates`, `Printf`, `Test`, `InteractiveUtils`, and `Base64` are loaded as root modules (`using LinearAlgebra`), not as public `Base.<stdlib>` submodules. Compiler/module-call special cases must either target a real Base submodule (`Base.Iterators`, `Base.Broadcast`, `Base.MathConstants`, etc.) or a private bridge inside the stdlib wrapper; they must not expose `Base.<stdlib>` property access, `using Base.<stdlib>`, or `Base.<stdlib>.<fn>` routes. Run `bash scripts/check_no_public_base_stdlib_routes.sh` to verify.
- **Structural debt inventory ratchet** (Issues #8327/#8329/#8332/#8333/#8334/#8335/#8336/#8337/#8460): `scripts/check_structural_debt_inventory.sh` pins the milestone-56 design-debt inventory so broad legacy categories cannot grow while the larger refactors proceed: Rust branches on Julia package/non-primitive type names, scattered env var / target triple / artifact literals, `.unwrap()` / `.expect()` sites, cross-crate `#[path]` boundary bypasses, safe FFI exports that accept raw pointers, large Rust files/functions, inline tests under `src/`, source-side `#[cfg(test)]` blocks over 200 lines, Julia `# Workaround:` comments without issue links, stale TODO references to closed #1447/#3510, and active-source `Issue #XXXX` placeholders. This is a ratchet, not a license to add debt up to the baseline: any intentional new instance needs its own Issue and a same-PR reduction elsewhere or a justified baseline update. Public/API-level Rust tests belong in `subset_julia_vm/tests/`; keep source-side test modules only for private white-box coverage. Run `bash scripts/check_structural_debt_inventory.sh` to verify.
- **Base cache schema fingerprint snapshot** (Issue #8444): `subset_julia_vm/src/compile/base_cache_schema_files.txt` lists the Rust sources whose serialized shapes affect persistent/embedded Base cache compatibility (`Instr`, VM compiled-program metadata, method-table wire structs, inference cache keys, and Core/Value type schemas). `scripts/audit_base_cache_schema_fingerprint.sh` hashes those files and compares the result plus `CACHE_VERSION` against `subset_julia_vm/src/compile/base_cache_schema_fingerprint.txt`. If a schema input changes, update the snapshot and bump `CACHE_VERSION` in the same PR so stale Base caches are rejected before payload decode. Run `bash scripts/audit_base_cache_schema_fingerprint.sh` to verify. The script is intentionally named `audit_*.sh` until Issue #8491 can wire it into `.github/workflows/ci.yml` with a token that has `workflow` scope.
- **FFI C header completeness and syntax** (Issue #8455): `subset_julia_vm_ffi/include/subset_vm.h` is the public C/Swift/Flutter contract for the native FFI crate. Every `#[no_mangle] pub extern "C" fn` exported from `subset_julia_vm_ffi/src/*.rs` must be declared in the header, and the header must parse as both C11 and C++17. Ownership policy for returned pointers must be documented inline in the header: direct `char*` returns and JSON-copy accessors are freed with `free_string`, while fields/borrowed accessors inside `CExecutionResult` live until `free_execution_result`. Run `bash scripts/check_ffi_header_compiles.sh` to verify.
- **iOS sample catalog schema and count** (Issue #8457): `Samples/samples.json` is the source of truth for iOS sample metadata. Its `category` values must match `CodeSample.Category`, `difficulty` values must match `CodeSample.Difficulty`, each entry must have exactly one backing `.jl` file, there must be no unlisted sample files, and README sample/category counts must match the catalog. Run `bash scripts/check_ios_sample_catalog.sh` to verify.
- **Memory-to-Array compatibility bridge zero-match audit** (Issues #3908/#3941/#4008): The legacy `memory_to_array_ref` compatibility bridge is retired. `scripts/check_memory_to_array_ref_allowlist.sh` now enforces zero `memory_to_array_ref(` matches across `subset_julia_vm/src`; any reintroduction must be issue-driven and justified against the upstream Memory / Array boundary in `julia/base/genericmemory.jl` and `julia/base/array.jl`. Prefer Memory primitives or Pure Julia `Array{T,N}` wrapper dispatch. Run `bash scripts/check_memory_to_array_ref_allowlist.sh` to verify.
- **Array carrier audit: `Value::Array` zero-match + `Value::ExprArgs` confinement allowlist** (Issues #4568/#6653/#6805/#6723/#6807): `scripts/check_value_array_allowlist.sh` enforces two policies across `subset_julia_vm/src` and `subset_julia_vm/tests`. (1) The legacy `Value::Array` enum variant is retired → zero `Value::Array` matches. (2) The Rc-backed mutable array carrier `Value::ExprArgs` (renamed from `ExprArgs`, #6807) is now **accepted as the dedicated `expr.args` representation** and confined: its sole runtime origin is `expr.args` (mutable `Vector{Any}` AST args), which need auto-freed reference semantics because `struct_heap` has no per-value GC — a heap-`StructRef` wrapper would leak one slot per transient `Expr` node. All *general* array values are the MemoryRef-backed pure-Julia `Array{T,N}` wrapper, so a plain array program produces zero `Value::ExprArgs` carriers (after the #6806/#6807 producer flips: compile-time literal, slices, HOF value-mode, ranges/RNG/matrix, zeros/ones/undef, linalg, …). The audit pins the variant *text* to an explicit `EXPR_ARGS_ALLOWLIST` (4 files: quote reconstruction in `lowering/macro_runtime.rs`, the variant definition + enum arm `value_enum.rs`, the `native_array_*` converter hub `array_value/mod.rs`, and the carrier unit tests `frame.rs`) — a file off the list that matches the variant is a new carrier site outside `expr.args` and must be justified; a no-longer-matching entry is stale and is removed. Public Array routes should return MemoryRef-backed Pure Julia `Array{T,N}` wrappers; `array_native_carrier_demoted_6653.jl` and `array_construction_routing_6649_tests` guard that surface. The carrier is accessed through the `native_array_*` helpers (`native_array_value_ref`, `native_array_ref_value`, `native_array_value_from_array`, `native_array_ref_from_value`), which live in the allowlisted converter hub. The `vm_array_benchmark` baseline lives in `benchmarks/results/vm_array_baseline_6805.md`. Run `bash scripts/check_value_array_allowlist.sh` to verify.
- **Public ArrayValue data access audit** (Issues #3927/#4018): Public array behavior must not read reshape-created arrays through stale `ArrayValue.data` clones. Real-valued broadcast uses `ArrayValue::get_linear_f64`, HOF/iteration array extraction must classify `shared_parent` arrays before raw storage access, and slice result builders must allocate through the Memory-first helper rather than direct `ArrayValue::new`. Interleaved ComplexF64 broadcast remains a typed-storage fast path with an inline `ArrayDataAudit:` classification. Run `bash scripts/check_array_public_data_access.sh` to verify.
- **Array constructor Memory-first helper audit** (Issue #3952/#4018/#6653): Public constructors now route through MemoryRef-backed wrappers; retained VM array constructor builtins and typed undef array instruction handlers are cache/VM compatibility fallbacks. When those handlers are touched, they must allocate storage through `ArrayValue::memory_first_*` helpers rather than open-coding `MemoryValue::undef_typed` plus `ArrayValue::from_memory` or calling `ArrayValue::undef_typed` directly. Run `bash scripts/check_array_constructor_memory_first.sh` to verify.
- **Array literal Memory-first helper audit** (Issue #3953/#4018/#6653): Public array literals now compile to Memory + wrapper construction. Retained `NewArray` / `NewArrayTyped` instruction handlers are compatibility builders and must allocate through `ArrayValue::memory_first_with_capacity` rather than open-coding `ArrayData::...Vec::with_capacity`, `ArrayValue::from_f64(Vec::with_capacity(...))`, or `TypedArrayValue::new`. Run `bash scripts/check_array_literal_memory_first.sh` to verify.
- **collect result Memory-first helper audit** (Issues #3954/#3960/#3961/#3966/#4061/#6653): Public `collect(range)`, `collect(tuple)`, `collect(array)`, and eager `collect(generator)` return MemoryRef-backed wrappers. Retained low-level collect fallback storage must still be materialized through `ArrayValue::memory_first_*` helpers rather than direct `ArrayValue::from_i64` / `from_f64`, direct `ArrayData` cloning, or silently collecting lazy Generator inner values without applying `f(x)`. `collect(::String)` routes through Pure Julia dispatch; the audit still blocks any direct `ArrayData::Char` fallback from returning. Run `bash scripts/check_collect_memory_first.sh` to verify.
- **broadcast/HOF result Memory-first helper audit** (Issues #3962/#4019/#6653): Public broadcast/HOF routes return MemoryRef-backed wrappers. Retained low-level VM broadcast and HOF fallback result builders must use `ArrayValue::memory_first_*` rather than direct `ArrayValue::from_f64` / `from_i64`, open-coded typed `ArrayData`, or HOF value-mode `TypedArrayValue::new` result builders. Run `bash scripts/check_broadcast_hof_memory_first.sh` to verify.
- **literal/REPL array Memory-first helper audit** (Issue #3963): `Literal::Array*` constant conversion and REPL persistence reconstruction must share the Memory-first `ArrayValue::memory_first_from_*` materialization boundary. REPL persistence must read logical array elements through `ArrayValue::get_linear` so reshaped/shared-storage arrays are not re-injected from stale raw `ArrayData`. Run `bash scripts/check_literal_repl_memory_first.sh` to verify.
- **Generated fixture chunk size audit** (Issue #3972): Generated fixture tests must stay batched enough that full release nextest does not regress toward one process per fixture. `FIXTURE_BATCH_SIZE` in `subset_julia_vm/build.rs` must remain at least 32, and the audit reports manifest entry count plus generated chunk count. Run `bash scripts/check_fixture_chunk_size.sh` to verify.
- **collect fallback inventory audit** (Issue #4052): Public `collect(itr)` must stay dispatch-first. Every retained native collect fallback boundary in `compile/expr/builtin.rs`, `compile/expr/call/mod.rs`, `vm/builtins_exec.rs`, `vm/exec/call_dynamic.rs`, and `vm/type_ops/iteration.rs` must carry a `CollectFallback:` tag documented in `docs/vm/COLLECTIONS.md` with an owner classification and upstream reference. Run `bash scripts/check_collect_fallback_inventory.sh` to verify.
- **CallDynamicBinaryBoth fallback inventory audit** (Issue #4262): Every retained fallback owner tag in `subset_julia_vm/src/vm/exec/binary_both.rs` must be documented in `docs/vm/BINARY_DISPATCH.md` with an ownership classification and upstream reference. Primitive numeric, BigInt, and BigFloat bootstrap branches must not silently expand the Rust arithmetic owner surface. Run `bash scripts/check_binary_both_fallback_inventory.sh` to verify.
- **Bundled Plotly.js trace coverage** (Issue #6850): Every `plotly.min.js` shipped to a host (iOS `SubsetJuliaVMApp/.../Resources/`, `web/`, Flutter `mobile/assets/plotly/`) must register all trace types the VM emits in `subset_julia_vm/src/plotting/plotly.rs` (`scatter`, `bar`, `heatmap`, `scatter3d`, `surface`). Plotly's partial `gl3d` build carries the 3D traces but NOT the cartesian `bar`/`heatmap` modules, and Plotly silently coerces an unregistered trace type to `scatter` — so a `bar` plot renders as a line graph. Only the full `plotly.min.js` carries both the 3D and cartesian traces; keep all three host bundles on the same full build. Run `bash scripts/check_plotly_bundle.sh` to verify.
- **Pure Julia base/ silent-stub audit** (Issue #4703, prevention for fix family #4701 / #3909 / #4694 / #5039): A "silent stub" is a `function NAME(args...)` in `subset_julia_vm/src/julia/` whose ENTIRE body is a single trivial `return <constant-or-bare-arg>` and whose positional args are all UNTYPED. This shape compiles as valid Julia and passes static analysis yet can silently return the wrong value for every input it should discriminate on — the `isvarargtype(t) = false` (#4701) and `unwrap_unionall(t) = t` (#3909) bugs. Every such helper in a swept file must be verified against `julia/base` and then either replaced with a real implementation or marked, in the comment block immediately above the `function` keyword, with `# INTENTIONAL_NOOP (Issue #NNNN): ...` (the trivial body is the correct semantics, e.g. a generic dispatch fallback or an optimizer hint sjulia does not need) or `# STUB(Issue #NNNN): ...` (a placeholder that IS wrong but is tracked by an open Issue). Run `bash scripts/audit_julia_base_stubs.sh` to verify. The script's `AUDIT_FILES` list is the set of swept files (currently `essentials.jl`, `number.jl`, `bool.jl`, `missing.jl`, `range.jl`, `broadcast.jl`, `iterators.jl`); extend it only after auditing every trivial untyped helper in a file. The `essentials_base_noop_helpers` fixture pins the observable behavior of the INTENTIONAL_NOOP helpers so they cannot be silently deleted as dead code. The script is intentionally named `audit_*.sh`, NOT `check_*.sh`: the `check_*.sh` CI perimeter requires a matching `.github/workflows/ci.yml` stanza, and pushing ci.yml changes needs the `workflow` OAuth scope the automation token lacks (see "When automation cannot update ci.yml" below, Issue #4714) — same developer-tool naming precedent as `fixture_julia_parity.sh` / `probe_base_api_parity.sh`. Issue #4705 tracks the eventual rename to `check_julia_base_stubs.sh` + CI wiring in a single maintainer PR.
- **Rust Debug repr catch-all in Value display** (Issue #4757, prevention for fix family #4725/#4727/#4729/#4735/#4755): In any `Display` / `format!` arm that walks `Value` children (Expr children, Dict entries, Pair components, etc.), the `_ => format!("{:?}")` catch-all must NOT be reachable for `Value::I8`/`I16`/`I32`/`I128`, `Value::U8`/`U16`/`U32`/`U64`/`U128`, `Value::F16`/`F32`, `Value::Bool`, `Value::Char`, `Value::Symbol`, `Value::StructRef`, `Value::Nothing`, or `Value::Missing` — these are all user-visible Julia values and have a known parseable form. The matrix fixture `io_no_rust_debug_leak_4757` asserts that `string` / `repr` / interpolation never emit Rust Debug tokens like `I128(`, `Str(`, `Char(`, etc. for those variants. Extend the fixture when adding new `Value` variants.
- **Feature-branch guard for `/auto-work`** (Issue #4798, prevention for direct-to-main commits): the `/auto-work` workflow requires creating `fix/<NNNN>-<slug>` BEFORE the first edit. `scripts/branch_guard.sh` fails fast when the current branch is `main` or `master` (use as a pre-commit hook: `printf '#!/usr/bin/env bash\nexec bash scripts/branch_guard.sh --quiet\n' > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit`). The script is intentionally not named `check_*.sh` because it's a developer-side guard, not a CI gate (same convention as `fixture_julia_parity.sh` / `probe_base_api_parity.sh`). Recovery if you already committed on main locally (and haven't pushed): `git branch fix/<NNNN>-<slug> && git reset --hard origin/main && git checkout fix/<NNNN>-<slug>`.
- **Narrow integer dispatch parity** (Issue #4791, prevention for fix family #4785 / #4787 / #4789): Any VM builtin or `dynamic_*` operation that takes a numeric argument MUST have explicit arms for all primitive integer widths (`I8`/`I16`/`I32`/`I64`/`I128`, `U8`/`U16`/`U32`/`U64`/`U128`) and float widths (`F16`/`F32`/`F64`), not just `I64` / `F64`. Signed overflow paths (e.g. `-typemin(Int8)`) must use `wrapping_*` to match Julia's two's-complement semantics. Compile arms must use `compile_expr` (preserving type) rather than `compile_expr_as(..., I64)` (forcing coercion that loses width). The `scripts/probe_base_api_parity.sh` matrix section + `numeric_narrow_integer_dispatch_matrix_4791` fixture catch missing arms; extend both when adding a new numeric operation.
- **Float-width parity** (Issue #4806, prevention for fix family #4802 / #4804 / #4807): `format_float_julia` (f64), `format_float32_julia` (f32), and `format_float16_julia` (f16) in `subset_julia_vm/src/vm/formatting.rs` are three parallel helpers with the same shape: NaN / Inf / `-0.0` handling, whole-number fixed-form, and (for f64 and f32 after #4803 / #4805) a scientific-notation arm for extreme magnitudes. When fixing a magnitude/format bug in one helper, check whether the same bug exists in the other two — most magnitude-related bugs apply to all widths because Rust's default `Display` is fixed-point for every float type. The `scripts/probe_base_api_parity.sh` matrix has at least one extreme-magnitude probe per width (Float64 / Float32 cells fixed; the Float16 cell currently surfaces #4807 as a known divergence); extend it when adding a new format path.
- **Base API parity sweep** (Issue #4782, prevention for the multi-issue series #4759 #4761 #4764 #4768 #4770 #4772 #4774 #4777 #4780): When wrapping an upstream Base function as a VM builtin, the signature must match upstream's published one. Hardcoded `args.len() != N` / `args.len() < N` rejections in `subset_julia_vm/src/compile/expr/builtin.rs` arms are a code smell — most upstream Base functions are variadic. Cross-check against the [Julia Base reference](https://docs.julialang.org/en/v1/base/base/) and add fixture cells for the variadic / kwargs / mixed-type forms. The `scripts/probe_base_api_parity.sh` developer probe runs a curated matrix of Base call shapes under both sjulia and upstream Julia and reports every divergence side-by-side — run it after any change in `vm/formatting.rs`, `compile/expr/builtin.rs`, or new Base wrapper additions. The script is NOT a CI gate (intentionally not named `check_*.sh`); it's a discovery tool, run by hand, so do not pin a "current divergence count" in this policy. Open or reference bug Issues for new divergences before relying on them as known gaps.
- **StructRef heap resolution at every display entry point** (Issue #4766, prevention for fix #4761; extended by #4774 for #4772 and #5038 for `Symbol`/`ToString`): Any new VM builtin or `Instr::*` arm that pops a `Value` and feeds it to `format_value` / `format_value_print` / `value_to_string` for user-visible output MUST first call `vm::formatting::resolve_struct_refs_for_format(v, &self.struct_heap)` (or do an inline top-level `Value::StructRef` deref via `self.struct_heap.get(idx)`). The format functions are deliberately heap-less; without resolution, heap-allocated structs (`Pair(1, 2)`, user structs) leak as `StructRef(heap_idx=N)`. Existing covered call sites: `BuiltinId::Print`, `BuiltinId::Println`, `BuiltinId::IOPrint` (since PR #4763), `BuiltinId::IOWrite` (since PR #4763), `BuiltinId::StringNew`, `BuiltinId::Sprintf`, `BuiltinId::Repr`, `BuiltinId::SymbolNew` (since #5038), `Instr::StringConcat` / `ConcatStrings` / `ToStr` / `ToString`. The resolution helper recurses through composite carriers (`Tuple`, `NamedTuple`, `Ref`, `QuoteNode`, `Struct`, `Memory`, `ExprArgs`, `Dict`); when adding a NEW carrier-walking format helper (e.g. a new `format_*_compact` arm) you must also add a matching recursion arm to `resolve_struct_refs_for_format` AND extend the matrix fixtures. **Enforced by `scripts/check_format_value_resolves_structref.sh`**: it scans the VM display-entry-point files (`vm/builtins_io.rs`, `vm/builtins_strings.rs`, `vm/builtins_macro/mod.rs`, `vm/exec/string_ops.rs`, `vm/exec/print.rs`, `vm/exec/error_handling.rs`) and FAILS if a sink call's argument is not the canonical heap-resolved local `resolved` (or a `for VAR in resolved_values/print_values` loop element), not wrapped in `resolve_struct_refs_for_format(`, not a `&Value::` literal, and not covered by an `// AUDIT(#NNNN)` allowlist comment in the preceding 8 lines. Error-message paths and inline-deref `match` arms are allowlisted via `// AUDIT(#4766)` comments. The FFI layer (`subset_julia_vm/src/ffi/`) is intentionally NOT audited — its `format_value` has no `struct_heap` access and renders a bare StructRef as the benign `<struct ref>` placeholder, not the Rust Debug `StructRef(heap_idx=N)` repr. The sibling matrix fixtures `io_no_rust_debug_leak_iobuf_4766` (IOBuffer / sprint / multi-arg print), `io_no_leak_container_struct_matrix_4774` (7 container shapes × 6 entry points = 54 leak guards), and `io_no_leak_symbol_entry_point_4766` (the `Symbol(x)` / `Symbol(args...)` entry point) ratchet coverage; extend them (and `io_no_rust_debug_leak_4757`) when adding a new display path or container type, and add a new `// AUDIT(#NNNN)` comment (not a window widening) for any genuinely-safe non-`resolved` sink. **Shallow-vs-deep gap (Issue #5234)**: the script's "canonical heap-resolved local `resolved`" rule matches on the *variable name* `resolved`, not on how it was produced — so a sink fed a local named `resolved` that came from a *shallow* top-level `if let Value::StructRef(idx) = ... deref (only the top value, not nested elements) still passes the grep. That is exactly how `BuiltinId::Print` / `BuiltinId::Println` and the `Instr::PrintAny` / `PrintAnyNoNewline` stdout entry points leaked `StructRef(heap_idx=N)` for array *elements* (`println([1 => 2, 3 => 4])`, `println([Foo(1), Foo(2)])`) while passing the audit: their `resolved` binding only dereferenced the top-level array, leaving nested `Value::StructRef` elements inside the backing `Memory`/`ExprArgs` to leak through `format_array_element`. #5234 switched all four to the deep `resolve_struct_refs_for_format`. Because the grep cannot tell shallow from deep, the **bare single-arg stdout `print`/`println` entry point × array-of-heap-struct variant is guarded by tests, not the grep**: the fixture `io_array_element_structref_5234` (string / repr / `sprint(print, …)` over arrays + comprehensions of Pair / Complex / user struct) and the Rust stdout-capture integration test `array_element_structref_5234_tests` (which calls `compile_and_run_str_with_output` so it exercises the actual `BuiltinId::Print`/`Println` + `PrintAny`/`PrintAnyNoNewline` instructions the fixture's `string`/`repr` path never reaches). When adding a display entry point that pops a *container* value, deep-resolve (do NOT settle for a top-level `Value::StructRef` deref) and add a stdout-capture cell. Run `bash scripts/check_format_value_resolves_structref.sh` to verify.

- **Native value ops resolve StructRef before compare/hash** (Issue #6694, prevention for the StructRef value-op family #6685 tuple-`==` / #6691 `in` / #6693 hash / #6709 `===`): immutable structs (`OneTo`, `UnitRange`, ordinary non-`mutable` user structs) live on the struct heap as `Value::StructRef(idx)`, so any native VM op that compares or hashes a `Value` by **structure** must resolve those heap refs to inline snapshots first — otherwise it compares/hashes heap indices and two separately-constructed but equal values are reported unequal (or hash differently). The canonical resolvers live in `vm/builtins_equality.rs`: `resolve_value_op_structrefs(value, heap)` (resolve ALL structs — used by `==`/`hash`/`in`), its borrowing `Cow` variant `resolved_value_op_structrefs(&value, heap)`, `self.resolve_immutable_structrefs(&value, ..)` (resolve IMMUTABLE structs only, used by `===`, which keeps mutable structs at reference identity), and the membership wrapper `values_equal_for_membership(a, b, heap)`. Covered handler arms: `BuiltinId::Egal` (immutable-only resolution; `struct_defs[type_id].is_mutable`, parametric structs absent from `struct_defs` correctly default to immutable), `BuiltinId::TupleEquals`, `BuiltinId::Hash`, `BuiltinId::_Hash`, and the `In` builtin via `values_equal_for_membership`. **Enforced by `scripts/check_native_value_ops_resolve_structref.sh`**: it anchors the four resolver helpers' existence and scans each `BuiltinId::{Egal,TupleEquals,Hash,_Hash}` arm in `builtins_equality.rs`, FAILING if an arm stops calling a resolver, plus verifies `builtins_types.rs` still routes membership through `values_equal_for_membership`. Adding a NEW native structural compare/hash op? Route its operands through one of the resolvers and add its `BuiltinId::` arm to `REQUIRED_HANDLERS` in the script. Regression coverage: fixture `operators/egal_immutable_struct_6709.jl` and the unit tests in `vm::builtins_equality::structref_equality_tests`. Run `bash scripts/check_native_value_ops_resolve_structref.sh` to verify.
- **Metaprogramming roundtrip gate** (Issue #7720): `scripts/check_metaprogramming_roundtrip.sh` runs a focused seed corpus under both upstream `julia` and `./target/release/sjulia`, comparing Test.jl pass/fail summaries for `Meta.parse` source printing, `Meta.parse` → runtime `eval`, and macro-returned `Meta.parse` values lowering back to IR. The corpus includes parser-internal head normalization seeds from #7753/#7754 and keyword-call `Meta.parse` eval / macro-return seeds from #7755. The script requires a release `sjulia` binary built with `--features repl`, so run `cargo build --release --bin sjulia --features repl` before `bash scripts/check_metaprogramming_roundtrip.sh`.

## Adding a New Audit Script (Issue #3112)

When adding a new `scripts/check_*.sh`:
- [ ] Add a `shellcheck scripts/check_NEW.sh` line to the `Shellcheck all audit scripts` step in `.github/workflows/ci.yml` (`code-audits` job)
- [ ] Add a `bash scripts/check_NEW.sh` step with a descriptive name and issue reference in `.github/workflows/ci.yml`
- [ ] Add a bullet to the Audit Policies section in this file (`docs/vm/CODE_AUDITS.md`)
- [ ] Verify the script exits 0 (passes) locally before opening the PR

Run this local self-check before opening the PR to catch missing ci.yml or docs registrations (Issue #3242):

```bash
for f in scripts/check_*.sh; do
  base=$(basename "$f")
  grep -q "$base" .github/workflows/ci.yml || echo "MISSING from ci.yml: $base"
  grep -rq "$base" CLAUDE.md docs/vm/CODE_AUDITS.md docs/vm/TESTING_GUIDE.md || echo "MISSING from docs: $base"
done
```

### When automation cannot update ci.yml (Issue #4714)

GitHub OAuth automation tokens without the `workflow` scope cannot
push changes to `.github/workflows/ci.yml`. Pushes that touch that
file are rejected at the remote with:

```
remote: refusing to allow an OAuth App to create or update workflow
`.github/workflows/ci.yml` without `workflow` scope
```

When you hit this (or anticipate it), pick one of these two fallbacks:

1. **Split the PR.** Land the script and the `CODE_AUDITS.md` bullet
   in this PR, and open a *separate* follow-up issue that quotes
   verbatim the diff that needs to land in `ci.yml` (shellcheck line
   plus the run step). A maintainer with `workflow` scope can apply
   the stanza in a one-line follow-up PR. See Issue #4705 for the
   reference shape (the issue body embeds the full script + ci.yml
   stanzas inline).
2. **Rename out of the audit perimeter.** If the script is
   *developer-only* and does not need CI enforcement, name it without
   the `check_*.sh` prefix so the `Verify all check_*.sh scripts are
   referenced…` audit (above) does not apply. See
   `scripts/fixture_julia_parity.sh` (PR #4713, Issue #4712) for an
   example of this pattern.

The long-term fix is to grant the automation token the `workflow`
scope so that the script + ci.yml stanza can ship in a single PR.
Issue #4714 tracks that operational change.
