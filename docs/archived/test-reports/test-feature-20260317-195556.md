## Per-Feature Details

### `juliar`
- **Role:** Intermediate Rust/Julia user evaluating the AoT CLI from docs alone
- **Use Case:** Compile a simple Julia source file to Rust, then build and run the generated Rust binary
- **What they tried:** Built `juliar`, generated Rust from a small Julia file, compiled the generated Rust with `rustc`, ran the resulting binary, and exercised documented flags such as `--stats`, `--comments`, `--emit-comments`, and `--pure-rust`
- **Discoverability:** Good. `README.md` and `docs/aot/README.md` make the AoT feature and `juliar` name easy to find.
- **Setup:** Partial. Building `juliar` worked, but the generated Rust used `subset_julia_vm_runtime`, so the plain standalone `rustc output.rs -o program` path did not work for this sample. The workspace-level `target/release/libsubset_julia_vm_runtime.rlib` path also matters.
- **Functionality:** Partial. The main runtime-linked flow worked end to end and printed the expected result. Two documented branches did not hold up: `--emit-comments` is not a real option, and `--pure-rust` still generated runtime-dependent Rust for a trivial typed program.
- **Expected vs Actual Outcome:** The core compile-to-Rust path works. The docs overstate the standalone path and expose at least one stale option name, so a user following the documentation exactly can take a broken path even though the feature itself is broadly functional.
- **Blocked steps:** None from sandbox or missing secrets. All tested commands stayed within the workspace or `/tmp`.
- **Friction points:** Workspace-target behavior is implicit, runtime-link requirements are underspecified, the unknown-option handling is permissive, and the README option list does not match the actual CLI.
- **Doc suggestions:** Replace `--emit-comments` with `--comments`, document that generated Rust may require `subset_julia_vm_runtime` even for simple programs, clarify that the `target/release` path is at the workspace root, and explain when `--pure-rust` is expected to succeed.

## Expected vs Actual Outcome

- **Expected:** A user can follow the docs, generate Rust, and compile/run the result with the documented commands.
- **Actual:** A user can generate Rust and run it successfully when using the runtime-linked `rustc` form, but the standalone path is not reliable for the tested sample, and one documented option name is wrong.
- **Expected:** `--pure-rust` should generate standalone Rust for simple typed input.
- **Actual:** `--pure-rust` still emitted `extern crate subset_julia_vm_runtime;` and failed to compile standalone with `rustc`.

## Issues Found

1. **Critical:** README option drift. The docs advertise `--emit-comments`, but the CLI only accepts `--comments`. Worse, passing `--emit-comments` prints `Unknown option: --emit-comments` yet still exits successfully and generates output, which can hide user mistakes.
2. **Critical:** `--pure-rust` did not produce pure Rust for a trivial typed program. The generated file still referenced `subset_julia_vm_runtime`, so the documented standalone `rustc` path failed immediately.
3. **High:** The README shows a standalone `rustc output.rs -o output_binary` flow before the runtime-linked variant, but the tested generated Rust required the runtime crate even without advanced features.
4. **Medium:** The docs do not clearly say that the relevant `target/release` directory is the workspace root target directory, not necessarily `subset_julia_vm/target/release`.
5. **Low:** The generated Rust included an unused `Value` import and redundant parentheses warnings for the tested sample.

## Suggestions

1. Update `README.md` to match the actual CLI flags, specifically `--comments` instead of `--emit-comments`.
2. Make unknown options fail with a non-zero exit code instead of printing a warning and continuing.
3. Either fix `--pure-rust` so it truly emits standalone Rust for simple typed programs or narrow the docs to explain current limitations.
4. Rework the AoT docs so the runtime-linked `rustc` flow is the default unless standalone output is guaranteed.
5. Clarify workspace-root `target/release` paths in both `README.md` and `docs/aot/README.md`.
