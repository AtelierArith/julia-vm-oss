## Per-Feature Details

- **Role:** Intermediate CLI user exploring the REPL from docs.
- **Use Case:** Follow README to launch the REPL, evaluate expressions, and exit cleanly.

- **Discoverability:** README clearly lists the `sjulia` command, installation steps, and command aliases.
- **Setup:** The `cargo run` invocation worked, but building from the workspace root triggered standard unused-variable warnings (observed previously in this repo as well).
- **Functionality:** Interactive session prints the banner, evaluates `x`, and exits; coloring and output match the documented REPL.
- **Expected vs Actual Outcome:** Expectation met; no blocking steps.
- **Blocked steps:** None.
- **Friction points:** Build warnings cluttered output but do not affect functionality.
- **Doc suggestions:** None for this section.

### `sjulia` scripting (`-e` and file)

- **Doc suggestions:** None.

### `sjulia --precompile-base` two-pass build
- **Role:** Performance-conscious builder following the README cache workflow.
- **Use Case:** Build once, generate `target/base_cache.bin`, and rebuild with `SJULIA_BASE_CACHE`.
- **What they tried:** Ran `cargo build --release --bin sjulia --features repl`, created `subset_julia_vm/target` so the cache could be written, invoked `./target/release/sjulia --precompile-base subset_julia_vm/target/base_cache.bin`, then rebuilt with `SJULIA_BASE_CACHE=... cargo build ...`.
- **Discoverability:** README describes the three steps, but the path assumptions (relative `target/base_cache.bin`) mismatch the workspace’s root-level `target` directory, so an extra `mkdir subset_julia_vm/target` was required.
- **Setup:** Creating the `subset_julia_vm/target` legacy directory was necessary to satisfy the tool, and the README does not warn that the `target` directory may need to be created or that the workspace-level `target` is used.
- **Functionality:** Once the directory existed, `--precompile-base` wrote the cache and the rebuild succeeded (with the usual compiler warnings).
- **Expected vs Actual Outcome:** The key outcome is achievable, but the docs understate the target path nuance.
- **Blocked steps:** None once the directory was created.
- **Friction points:** The write error before creating the directory and the repeated compiler warnings.
- **Doc suggestions:** Clarify that the cache command writes to `subset_julia_vm/target/base_cache.bin` (or the workspace root’s `target`) and that the directory must exist beforehand.

## Expected vs Actual Outcome

- **Expected:** The README workflows are sufficient to run the REPL, evaluate scripts, and precompile Base.  
- **Actual:** REPL and script execution worked exactly; the cache workflow requires manually ensuring the `target` directory exists because the command writes into `subset_julia_vm/target`.

## Issues Found

1. The precompile cache step assumes `subset_julia_vm/target` already exists, which caused an “Failed to write cache file” error until the directory was created.
2. Compiler warnings (unused variables) appear on every build, but these are pre-existing and did not block the flows.

## Suggestions

1. Mention in the README that `./target/release/sjulia --precompile-base target/base_cache.bin` writes under `subset_julia_vm/target` and that the directory must exist (or create it as part of the workflow).
2. Consider silencing or documenting the existing compiler warnings so they do not look like regressions in a user tutorial.

## Commands Run

```bash
cd subset_julia_vm && printf 'x = 10\nprintln(x * 2)\nexit()\n' | cargo run --bin sjulia --features repl --release
cd subset_julia_vm && cargo run --release --bin sjulia --features repl -- -e "println(1+2)"
cd subset_julia_vm && cargo run --release --bin sjulia --features repl -- /tmp/sjulia-file.jl
cd subset_julia_vm && cargo build --release --bin sjulia --features repl
mkdir -p subset_julia_vm/target
./target/release/sjulia --precompile-base subset_julia_vm/target/base_cache.bin
SJULIA_BASE_CACHE=$(pwd)/subset_julia_vm/target/base_cache.bin cargo build --release --bin sjulia --features repl
```
